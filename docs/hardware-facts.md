# 硬件事实清单

> **研究与设计之间的窄接口。** 我们的 SDK 设计只从这里取硬件事实，不直接引用厂家 SDK 的行为。
> 厂家 SDK 的分析（`research/vendor-analysis/`）是这些事实的**来源之一**，不是规格。
>
> 每条一行：**事实 → 来源 → 可信度 → 证据**。新事实先在 research 里论证，再在这里落一行；
> 真机确认或推翻时改这一行的「来源」和「可信度」，不在设计文档里各自改。
>
> **只收硬件事实。** 「厂家这样用」不是硬件事实，放 §8；「我们这样用」是设计决定，放设计文档。
> 行号不重排：移走的行留一行指向新位置，免得别处的引用失效。

## 怎么读这张表

**规格优先级**：PR0002（厂家关节模组 CANopen/CiA402 文档）+ 真机实测 > 我们自己的需求 > 厂家 SDK 的行为。
厂家 SDK 的行为只当提示：它说明「这样做至少在厂家那里能跑」，不说明「必须这样做」。

| 来源标记 | 含义 |
|---|---|
| **PR0002** | 关节模组协议文档（网页版 Rev 1.0）。协议正本 |
| **文档** | 其他厂家文档：`CANopen-V0.6.xlsx`、`_V1.0.1.docx`、`V1.3.xlsx`、控制器用户手册 |
| **配置** | 随包 `usr/etc/` 下的 YAML |
| **反汇编** | 厂家二进制的静态阅读，片段在 `research/evidence/disasm/` |
| **qemu** | 厂家二进制在 qemu + 伪造 `/dev/mem` 下实际跑过 |
| **真机** | 在机器人上测过。**目前没有任何一条** |

| 可信度 | 含义 |
|---|---|
| **高** | 两个独立来源一致（通常是文档 + 反汇编），或 golden vector 已写成断言 |
| **中** | 单一来源，没有反证 |
| **低** | 推断，或来源本身有笔误史 |
| **⚠️ 冲突** | 来源之间互相矛盾，设计上必须两种都能处理，或等真机定案 |

证据列里的 `CPC` = [`can-protocol-comparison.md`](../research/vendor-analysis/can-protocol-comparison.md)，
`L0` = [`l0-interface.md`](l0-interface.md)，`L2` = [`l2-executor-interface.md`](l2-executor-interface.md)，
`HA` = [`hardware-acceptance.md`](hardware-acceptance.md)。

## 8. 厂家栈的做法（只是提示，不是规格）

这些是厂家 SDK **怎么用**硬件的，记下来是因为它们说明「这样做至少能跑」。我们的设计可以不同；
不同的地方在设计文档里写理由。

| # | 厂家的做法 | 对我们意味着什么 |
|---|---|---|
| 8.1 | 每路每拍一帧：有设定点发 `0x200`，空闲发 `0x80` | 空闲拍发什么是我们的决定（`l2-executor-interface.md` §2.3） |
| 8.2 | 只发 SDO，从不解析 `0x580` 应答 | 我们要读应答；厂家没读并不说明应答不存在 |
| 8.3 | 不发心跳、不发 NMT | 喂狗靠周期控制帧 |
| 8.4 | 从没发过 MIT 帧 | MIT 只能照文档写，真机验证 |
| 8.5 | `UseLimit` 打开时每拍过速度 / 加速度限制器；随包配置里是关着的 | 我们的安全门不可关（`l2-executor-interface.md` §5） |
| 8.6 | rad → cnt 向零截断（`fcvtzs` / Eigen cast，反汇编，CPC §2） | 我们四舍五入：最大误差减半，正负对称，`cnt → rad → cnt` 恒等（`wire.hpp`） |
| 8.7 | 位置模式用 CSP（`0xC6` 子帧模板，反汇编，CPC §1.1） | 至少说明 CSP 下按拍发目标能跑；我们也用 CSP，理由写在 `l2-executor-interface.md` §2.3 |
| 8.8 | 本机型控制周期 2 ms（`Resample: 0.002`，其他机型 5 ms；配置 + 反汇编，CPC §1.1） | 说明 2 ms 在这台硬件上能跑；我们的周期按实测定（`l2-executor-interface.md` §2.1） |
| 8.9 | 使能 / 失能 / 清错走 SDO `0x6040` 的 DS402 序列（反汇编，CPC §3） | 我们走控制字节（2.2），SDO 只用于配置与诊断（`development-plan.md` 2.1） |
